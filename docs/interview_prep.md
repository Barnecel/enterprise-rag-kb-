# 面试复盘 & 项目速答手册（企业知识库 RAG 系统）

> 适用场景：技术面试被拷打时的自救手册。所有数字来自本地压测/监控真实采集，非编造。

## 一、项目一句话定位
混合检索（BM25+向量）+ 多模型热插拔 + 评测驱动的企业级 RAG 问答平台。
Flask + Vue3 + LangChain + ChromaDB + Cross-Encoder + 本地化大模型(Qwen3)。

## 二、真实性能指标（压测 + Prometheus 实测）

### 检索管线（RAG 内核，毫秒~秒级）
| 阶段 | P50 | P95 | 备注 |
|------|-----|-----|------|
| BM25 词法召回 | 10ms | 50ms | jieba 分词 |
| RRF 倒数排名融合 | 10ms | 10ms | 双路合并 |
| Vector 稠密召回 | ~2s | >10s | 含 embedding API 调用，受本地端点波动影响 |
| Cross-Encoder 重排 | 1s | 2s | BAAI/bge-reranker 精排 |
| 检索全链路 | ~3s | — | 相对生成可忽略 |

### 端到端（Locust 20 并发压测）
- `/api/qa/ask`：P50=53s，P95=154s，P99=169s，0 失败
- `/api/auth/login`：P50=0.49s
- 长杆 = **LLM 生成**（本地 9B / 局域网 27B 算力受限），非检索管线

### 结论话术
> "检索与重排全链路在秒级内完成，端到端 TTFT 的长杆是本地大模型生成。
> 优化方向：语义缓存命中（热点问题跳过检索+生成）、模型量化/蒸馏、流式首 token 优先返回。"

## 三、面试高频问题 + 标准答

### Q1：为什么用混合检索而不是纯向量？
A：BM25 保证词法精确召回（专有名词、编号、法条），向量捕语义泛化；
RRF 融合避免单路权重主导；任一路故障另一路兜底，Recall@5 实测 1.0。

### Q2：父子索引解决什么？
A：子块小（精准匹配）但上下文碎；父窗口（完整段落）作生成上下文。
1323 章节块语料上，子块命中+父窗口作答，Recall@5=1.0 且答案可读。

### Q3：如何保证多租户/密级隔离？
A：文档带 tenant_id + doc_level + 显式 ACL；检索前拼 WHERE 过滤，
Chroma 元数据过滤 + MySQL 授权双库同步，前端按权限显隐。

### Q4：模型热插拔怎么实现？
A：注册表模式，LLM/嵌入配置存 DB；切换经 `hot_swap_llm`/`hot_swap_embedding`，
LLM 切换即清语义缓存，嵌入切换先探测维度不兼容则要求重建向量库。
**踩过的坑（已修）**：① 启动未加载 DB 激活模型，重启丢切换；② 嵌入误用 LLM 的 api_key。

### Q5：评测体系怎么建？
A：57 题双粒度金标（文档级 Recall + 章节关键词命中），以评测为安全网做零行为变更重构；
LLM-as-Judge A/B 盲评（位置随机化防偏），9B vs 27B 量化 99.3 vs 95.3（200 分制）。

### Q6：可观测性怎么做的？
A：Prometheus 埋点（HTTP 延迟、检索各阶段、缓存命中、生成延迟）+ /metrics 暴露 +
Grafana 面板；Locust 压测出 P50/P95/P99。缓存命中率/检索分解均可直接看图。

### Q7：最大技术挑战？
A：OCR 断行导致"检索/评测/验证同时失明"（CJK 不可见换行符），
正则连通 + 单测固化，Recall 从 0.67 恢复到 1.0。

## 四、被追问时的安全边界
- 缓存命中率具体数字：看 Grafana `cache_hit_total/(cache_hit+cache_miss)`，本机未跑满不做预估
- 并发上限：Chroma 单机 ~150 QPS 估算值，未做分布式压测验证
- 绝不报编造数字；答"我项目里埋了点，实际跑一下就有，结论是长杆在生成"
